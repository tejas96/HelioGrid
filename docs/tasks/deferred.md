# Deferred — found during a task, outside its scope

A row is work found during a task but outside its scope.
A row reopens when its `reopens when` cell is met.
When a task starts, its met rows are listed, and the owner decides whether one joins the task.
A row is deleted in the change that ships it.
A new row goes at the end and takes the highest id this register has ever held, plus one: an id is
never reused, because shipped tasks cite rows by id.

A `reopens when` cell takes one of four forms; `<id>` may be a part's id (`T-M01-005f`), never a
struck task or a part merged into another, which never fire:

- `T-<id> starts` — met when its build begins (its RFC heading is written); a row that stays then
  gets a new trigger in that build.
- `T-<id> ships` — met when it reads `shipped`.
- `touches <path>` — met when a file a plan changes sits under that path (a folder ends with `/`).
- `owner: <what>` — waits on the owner.

A cell may join two forms with ` · `, as in `owner: rule the guard's access type · touches apps/api/src/common/auth/access.ts`.
