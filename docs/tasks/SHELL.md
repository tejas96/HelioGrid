### T-SHELL-007 · The shell's data flow — my membership, the coach-mark count and the home choice
**Type:** engine · **Tier:** P0
**Status:** shipped (#198)
**PRD rows:** M01-16 (P1), MS12-19 (P0)
**DESIGN:** none — an engine task; the surfaces are `T-SHELL-001` (375) and `T-SHELL-008` (1536).
**Risk:** HIGH — a new API route pair writing `tenant_membership` (tenancy), `packages/contracts`, `packages/db`'s schema file and `packages/data`'s session store.
**Why:** Both shells read the same facts — which company, which home is in force and which presets are composed into it, how many coach marks I have passed — and write two of them; without one flow in `packages/data` each platform would fetch and hold them its own way, a dismissal would live in a browser's storage instead of on the membership (`F4-36`), and neither shell screen could be built under the size signal (`/start` §2).
**Scope:** **In** — `domain`: the coach-mark maximum as one constant, `SessionSnapshot.chosenHome` · `db`: the membership check reads that constant (no migration) · `ui`: `MAX_STEPS` becomes that constant · `contracts`: two routes on the tenant router, OpenAPI re-emitted · `api`: the controller, service and repository halves of the two routes · `data`: the tenant repository's two calls, the session store's `chooseHome`, the `useShell()` hook and its query keys. **Out** — every rendering and every state (`T-SHELL-001`, `T-SHELL-008`); **why a session ended** — split to `T-SHELL-009` at this `/start`: the store only learns an expiry at boot, so a client-side reason goes wrong on any phone that stays in memory past its window, a 5xx refresh already signs a person out, a deactivated member's refreshed call answers 403 rather than 401, and the shell unmounts in the same emit that would carry the reason — four faults in the transport and the store that are a task of their own; the pack's `dataRights` value: the key has no type anywhere (`packages/domain/src/market/pack.ts:18`) and `T-FCORE-009` is parked, so `useShell` carries no field for it and fetches no pack; the availability pill (`T-M07-027`); search and the bell (`T-SHELL-002`, `T-SHELL-003`); the sign-out call itself (exists, `T-M01-025`); whether `CoachMarkSequence` gains a per-step callback (`T-SHELL-001`, a `ui` contract change there). **Size** — about 16 files, about 450 lines, no migration.

**Data model:** none new — reads and writes `tenant_membership.coach_marks_dismissed` (`T-M01-025`, migration 0002: `smallint`, check `0..3`, `FOR ALL` tenant policy, `SELECT, UPDATE` granted to `app_user` at `0002_identity_spine.sql:133-136`), found by the unique key `tenant_membership_tenant_user_key` (`tenant_id`, `user_account_id`); reads `tenant.company_name` through `GET /tenants/me`. No table, no column; the schema file's check reads the domain constant and generates the same SQL.
**Contract:** `packages/contracts/src/tenant.ts`, additive, access `'member'` (the session's own membership, like `PATCH /users/me`; no capability row): `myMembership` — `GET /tenants/me/membership` → 200 `{ coachMarksDismissed: 0..3 }` · 401 · 403 (a session with no company) · 404; `updateMyMembership` — `PATCH /tenants/me/membership`, body `{ coachMarksDismissed: int 0..FIRST_RUN_COACH_MARKS }` → 200 the stored row · 400 · 401 · 403 · 404 · 422 `DOMAIN_RULE_VIOLATION` when the count is below the stored one (a pass is never undone). No id on the path: the row is the session's tenant and user. The body carries no roles and no status — roles live in the session projection, and status is `active` for any caller `'member'` admits. The session projection and the auth router do not change.
**Depends on:** `T-M01-025` (shipped, #40 — the column, `GET /tenants/me`, the guard, the store) · `T-FPLAT-025` (shipped, #51 — `centreVerbFor`, `standingDestinationsFor`) · `T-M13-006` (shipped, #52 — `composedHome`, `homesOf`).
**Ruled at `/start`:**
- **The shell's facts are ONE hook, `useShell()` in `packages/data/src/react/`** (Law 11): the home in force and the composed presets (`composedHome(roles, chosen)`), the switcher's list (`homesOf`), the centre verb and the four slots (`T-FPLAT-025`), the tenant's name, the coach-mark count, `passCoachMark(k)`, `dismissCoachMarks()` and `chooseHome()`. Each platform renders it; neither computes it. Its reads are keyed by the tenant id, and the provider already clears the cache when the user changes (`packages/data/src/react/provider.tsx:20`).
- **The count is marks PASSED.** Moving past mark `k` writes `k`; dismissing the run or finishing it writes `FIRST_RUN_COACH_MARKS` — dismissing is forever, as `CoachMark.types.ts:45` says. The next landing shows the marks after the count, none once it is 3.
- **The chosen home is the session store's, in memory** — `chooseHome(preset)`; never persisted (`M13-09`, `F4-36`); a sign-out's fresh snapshot carries none; a preset no longer held falls back to the ladder (`composedHome`).
- **A pass is a server write, never a browser key.** The hook cancels the count's in-flight read, raises the cached count to the new value at once, and `PATCH`es it; a 422 refetches, so the server's count wins; a lost network leaves the cached count until the next read, which may show a mark again — accepted: a mark seen twice costs one tap and loses nothing.
- **The write is one conditional statement.** `UPDATE … SET coach_marks_dismissed = $n WHERE tenant_id = $t AND user_account_id = $u AND coach_marks_dismissed <= $n RETURNING coach_marks_dismissed`, in the tenant transaction; on zero rows, one read by the same key in the same transaction: no row → 404, a row → 422. Two devices or two taps can never move the count down.

### T-SHELL-009 · Why a session ended — the refresh names the reason, the transport reports it, the store holds the `ended` fact
**Type:** engine · **Tier:** P0
**Status:** shipped (#199)
**PRD rows:** M01-07 (P0), MS12-19 (P0)
**DESIGN:** none — an engine task. The state it serves is drawn as Frame 8 "access removed" of `SCR-SHELL-01` (`HelioGrid-UX/SCR-SHELL-01 App Shell - Mobile.dc.html`): the top bar keeps the product mark and the company's name, the body is one message, no destinations. It renders at `T-SHELL-001` (375) and `T-SHELL-008` (1536). The sign-in door (`T-M01-001`, shipped) draws no ending; that gap is a `docs/tasks/deferred.md` row.
**Risk:** HIGH — the API's refresh, the contract, and `packages/data`'s transport and session store: who is signed out, and why.
**Why:** A person whose access was removed must see "your access was removed" — gracefully, no crash, no data lost on the device (`M01` edge `S1.wrong.4`) — and never a false reason. Split from `T-SHELL-007` at its `/start`, whose second actor found the client-side reason wrong four ways on code already on `main`.
**Ruled at /start (one reason each):**
- **The SERVER names the reason, the client never guesses it.** Only the server knows a membership was deactivated. So the refresh answers a session whose company membership is `deactivated` with 401 `ACCESS_REMOVED`, and every other refusal (signed out, signed out everywhere, another tab, expired, unknown) with 401 `UNAUTHENTICATED`. This retires the split's candidate fix — a client-held expiry moved by an `onSessionRenewed()` signal — because the client no longer infers anything from an expiry. The words read true in every case: only a real removal says "removed".
- **Access removed goes to the door now, carrying its reason; the hold inside the shell lands with `T-SHELL-001`** (owner ruling at `/ship`, on `break-it-reviewer`'s finding). The drawing holds the person inside the shell (Frame 8 keeps the company's name in the top bar), but no shell renders Frame 8 yet: held now, a removed person would sit on the placeholder home with no message, no way out and every call failing, where `main` sends them to the door. So every removal moves the snapshot to `anonymous` with `ended` set (`tenantId` the company, or null when found at boot), which the door can read; `T-SHELL-001` makes the hold when it builds Frame 8 — three edits in `session-transitions.ts`, named on the Used-by line.
- **Deactivated wins over revoked or expired.** The deactivation's own sweep revokes the sessions it ends, so a revoked session whose active-company membership is deactivated answers `ACCESS_REMOVED`; a revoked, expired or unknown session whose membership is NOT deactivated answers `UNAUTHENTICATED`. The rule is domain's `refreshVerdict(life, membership, now)`, beside `admit`; the api only calls it.
- **Once at the door, `ended` stays until a sign-in or a sign-out.** A later loss of either kind changes nothing — two shell reads 401 together, and the second refresh can go out with a cookie the first answer already cleared and come back `UNAUTHENTICATED`.
- **The web asks for a refresh on a mid-session `NO_CREDENTIAL` too.** The web's token cookie dies with the token and the session cookie is sent only to `/auth`, so after ten minutes every ordinary web call carries nothing and answers `NO_CREDENTIAL`, and the transport skips the refresh — the web session dies at ten minutes today and no reason ever arrives. In browser mode a `NO_CREDENTIAL` on a route outside `/auth`, while `canRenew`, posts the refresh; a call under `/auth` (the boot check) carries the session cookie when there is one, so its `NO_CREDENTIAL` still means nothing to renew and spends nothing.
- **Every other loss opens the door, as today, with no reason shown.** No drawing and no row asks for a "you were signed out" message, so none is built — nothing false is said.
- **A refresh that fails any other way is not a loss.** Mid-session, a 5xx, 429, a timeout or a lost network hands the REFRESH's own failure to the caller (retryable where it is), and the person stays signed in. At boot the store is still `checking`: a boot check that fails for any reason but a loss goes to the door, as it does on `main` — a boot retry is no row's and is written to `docs/tasks/deferred.md`.
- **The deactivation's two writes stay as they are.** The refresh reads the membership itself, so a revocation sweep that fails after the flip cannot keep access past the token's ≤10 minutes; a cross-module transaction adds nothing `D1` needs.
**Scope:** **In** — `packages/contracts` (the refresh's 401 codes) · `apps/api` auth (the refresh's decision and its refusal) · `packages/domain/src/auth/` (the loss vocabulary, the `ended` fact, the transitions reducer, the refresh verdict) · `packages/data` (the transport reads the reason, stops calling a failed refresh a loss, and refreshes on the web's mid-session `NO_CREDENTIAL`; the store applies the reducer) · `apps/api/tests/support/fixture.ts` (a seeded session may carry a known secret, an expiry and a revocation, for the refresh tests). Both platforms share this one store and transport; no screen changes, and the web's sign-in is driven once as a landing (Q8). **Out** — holding a removed person inside the shell, rendering Frame 8 and its words: `T-SHELL-001`, `T-SHELL-008`; the door's words for an ending: `T-M01-001` · roles changed mid-session reaching the snapshot: no row here, written to `docs/tasks/deferred.md` · a client-held expiry and `onSessionRenewed()`: not needed, see the first ruling · the deactivation itself and the Team screen: `T-FPLAT-003`, `M01-19`. **Size** — ~18 files, ~800 lines (about half tests), no migration, one route's error set.
