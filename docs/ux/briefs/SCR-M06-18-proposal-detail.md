## States

- **loading** — the proposal, its versions and its tracking loading.
- **empty** — a proposal with no version yet (draft): status and actions render for the draft; no tracking exists before mark-shared starts the clock.
- **error** — a failed load or a failed share act stated plainly.
- **draft** — the status machine's first state (draft → shared → accepted / declined, with superseded — `M06-45` context).
- **shared** — the version marked shared; the funnel timestamped; tracking and follow-up armed.
- **opened-tracking** — the open recorded as the evidence of record; the rep notified (`proposal_opened`).
- **viewed-duration** — viewed-for-how-long tracking.
- **accepted** — acceptance arrived from the customer link.
- **declined** — decline arrived from the customer link.
- **superseded** — a newer proposal replaced it on the lead.
- **stale-regenerate-offered** — staleness stated on the detail (derived, never stored) with Regenerate offered.
- **design-survey-review-needed** — read on the proposal on open, **before any share act**: the design this proposal was built on carries the "survey updated — review needed" marker, the superseding survey version is named, and the route to the design's review (SCR-MS-03) is offered as the corrective action. This is a distinct condition from **stale-regenerate-offered**: `M05-13` applies nothing automatically, so no pinned design value has moved and `M06-46`'s fingerprint comparison does not fire — Regenerate is not the remedy here, the designer's review is. Never communicated only by a colour, only by absence, or only after the rep tries to send (`M05-13`, owner ruling 2026-08-04 Q24; `F8-18`).
- **sent-version-pinned-during-review** — a version already `shared` when the supersession lands: it stays pinned and never mutates — its figures, its pinned inputs and its customer-facing rendering are unchanged by the review, and the review-needed state is stated about the design without restating the sent version's numbers as provisional (`M05-13`; `F8-15`). Only draft versions are held from sending.
- **upgrade-offered-diff** — the Path B upgrade offer showing the differences and tier changes before anything commits.
- **share-sheet** — the share surface: automatic send from the connected transactional channel where one exists; always Download PDF, Copy link, composed message (copy-to-clipboard + deep link into the rep's own messaging app); explicit mark-shared on the fallback.
- **send-blocked-survey-superseded** — the share sheet with its send blocked: a draft proposal built on a design carrying the "survey updated — review needed" marker cannot send until the review clears, the stated reason names the superseding survey version, and the route to the design's review is offered (`M05-13`, owner ruling 2026-08-04 Q24). The block lands on both of `M06-53`'s send acts — the automatic send from the connected transactional channel, and the explicit mark-shared act that moves the version to `shared` and starts the clock. Whether `M06-53`'s always-available manual path (Download PDF, Copy link, composed message) still renders behind the block is **not pinned by these rows** — designer decides and notes the decision; the reason and the route to the review render either way. This state is the refusal, not the warning: it must never be the first place the rep learns of the condition (**design-survey-review-needed** carries that, per `F8-18`).
- **delivery-failed-alternative-offered** — the connected channel's failure report shown as the visible delivery failure, with an alternative connected channel (SMS/email) or the composed manual path offered.
- **no-delivery-state-fallback** — the copy-paste fallback: no delivered state exists anywhere; only shared → opened → viewed-for-how-long.

## Numbers carrying provenance

- **Status timestamps** (shared / opened / accepted / declined moments) — record facts; the mark-shared act is what timestamps the funnel.
- **Viewed-for-how-long durations** — the product's own open evidence, shown as tracked.
- **Delivery states** — only as the connected channel reports them; never on the fallback path (an absence that must be designed, not papered over).
- **Version numbers** — server-assigned record facts.
- **Upgrade-offer diff figures** — each shows its tier change (`estimated`/`assumed` → `derived`) before anything commits; a tier change is shown, never silent.
- **Staleness** — derived by comparison, stated wherever read; any money shown from a stale version renders provisional, never final (`M06-41`'s law rides every money render).
- **The superseding survey version** — named on the review-needed state and in the blocked send's stated reason; a record fact of the survey's versioned append, carried from the design's pinned inputs, never a computed figure (`M05-13`). No money figure on this proposal changes because of it — `M05-13` applies nothing automatically, so a held draft's figures stay exactly what its version pinned.
