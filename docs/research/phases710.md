## 1. WHAT EACH PHASE SPECIFIES

### Phase 7 — Project management (light) · 7 screens
**Thesis:** a status + documents + money tracker, NOT PM software ("replace the notebook, not sell MS Project"). Killer feature owners pay for: **payment collection against tranches** (cash-flow leak on passed milestones). Two governing truths: **(a) days-in-stage is the ONLY metric** (never %, never burndown); **(b) every blocker names WHO is waiting** — us / customer / DISCOM / material — and "waiting on customer" protects the EPC from absorbing blame.

**In-v1 vs NOT-in-v1 (explicit scope line):** IN = stage board, payment collection vs tranches, document checklist, blockers with named reason, customer progress link. NOT = inventory/stock, purchase orders to suppliers, crew rostering/scheduling engine, Gantt/dependencies, procurement, O&M, AMC, tickets.

**The 9 project stages after Won:** Won → Material ordered → Dispatched → Installation → Electrical & metering → DISCOM inspection → Commissioned → Subsidy claimed → Handed over.

Screens:
- **7.1 Mark won → project auto-created.** New action on existing lead detail (Phase 2). Collects ONLY final value (pre-filled from accepted proposal, editable) + expected installation date. On confirm, project created automatically — customer, design, accepted proposal, payment tranches all carry over; user lands on 7.3 pre-populated. Edge: won on a deal with nothing paid → booking tranche now due (hands to 7.4). Never re-enter customer (re-typing = data divergence).
- **7.2 Projects board.** Every won deal by stage. Each card: customer, system size, value, **days-in-stage**, payment collected vs due, blocker flag. Aged/stuck cards must surface (not sink to bottom). Sample data: Priya Sharma·Nashik·8.2kWp·₹3,51,847·Installation·day 2·70%; Deshmukh Textiles·250kWp·₹1.28Cr·DISCOM inspection·day 34·🚩waiting on DISCOM·80%; Rohit Mehta·10kWp·₹5,60,000·Material ordered·day 1·10%; Kavita Joshi·7.6kWp·₹4,10,000·Commissioned·day 3·🚩waiting on customer(payment)·90%. Edge: a project installed but stuck a month in commissioning must NOT read "nearly finished." Empty state explained. Mobile = ONE column + stage filter (kanban doesn't fit a phone); desktop = full board across stages.
- **7.3 Project detail.** The screen ops lives in. Holds: stage timeline w/ current stage + days-in-stage + advance action; approved design + accepted proposal (links); payments summary (→7.4); documents summary (→7.5); active blockers (→7.6); activity log (stage moves, payments, uploads); "What the customer sees" preview of Phase-4 link. **Advancing a stage is the core action** — updates customer link, and completing a stage makes matching payment tranche due. Installation stage opens existing InstallationSheet (do not rebuild). Edge: cancelled-after-Won allowed with a reason, clearly no longer counted as active revenue.
- **7.4 Payments.** Same **10/60/20/10** tranches from proposal builder (Phase 3.4) — do NOT invent figures. On ₹3,51,847: 10% booking ✅ 12 Aug ₹35,185; 60% material dispatch ✅ 14 Aug ₹2,11,108; 20% installation 🔵 due now ₹70,369 [Copy request]; 10% commissioning ⬜ upcoming ₹35,185. Due tranche actions: "Copy request message" (ready-to-paste WhatsApp; app does NOT send), "Mark received" (mode UPI/NEFT/cheque + date + attach receipt). Rule: **never block the customer progress link over money.** States include overdue (flagged for chasing, link untouched); overdue also surfaces on board + owner dashboard.
- **7.5 Document checklist.** 8 docs, each status **pending · uploaded · verified**: Signed proposal, Advance receipt, Net-metering application, DISCOM approval, Subsidy application & sanction (PM Surya Ghar), Commissioning certificate, Warranty documents, Handover pack. Some auto-arrive from earlier stages (signed proposal, advance receipt). Subsidy docs most important to customer (it's their money) — a missing/pending subsidy sanction must be visible not buried. Edge: rejected/re-upload-needed with reason. Completion enables handover pack (7.7).
- **7.6 Blockers.** Every blocker names WHO + reason + start date: waiting on DISCOM ("net-metering applied 15 Aug, typically 3–6 weeks"), waiting on customer (site access/document/payment — records start date, the EPC-protecting one), waiting on material (expected date; customer sees "material ordered" not supplier's problem), waiting on us (honest). Setting a blocker updates customer link with the honest waiting line (prevents "what's the status?" calls). Clearing resumes + updates link.
- **7.7 Handover.** Assembles pack (warranty docs, commissioning cert, net-metering approval, invoice). "Download pack" + "Copy link" (rep shares, app doesn't send) + a "how to read your generation" pointer + a quiet referral ask ("know someone thinking about solar?"). On completion project CLOSED; customer link flips to Phase-4 State F "your system is live." States: not ready / ready / handed over / reopened (rare, allowed).

**Roles gap noted:** Stage 8 needs a Coordinator/ops + Installer/crew actor, not in the six preset roles (D27); interim = use "coordinator" and keep install checklist financial-free. (Phase 8 resolves this → coordinator = Manager; installer deferred.)

### Phase 9 — Dashboards & the rest · 5 screens
**Thesis:** owner's honest, decision-oriented view — NOT a KPI wall (D37). Every tile must answer "what do I do about this?" Daily driver stays My Day; this is the weekly/monthly step-back. **These screens READ only — never create (D37);** everything deep-links to the real lead/proposal/project.

**Honesty rules (D37), held on every figure:** forecast is a projection labelled "expected, not promised," never in the same total as won; won means SIGNED, cancelled-after-won stops counting immediately; agent contribution is correlation not attribution (link to Phase 6, don't re-claim credit); **visibility follows role (D20)** — rep sees own, manager team, owner everything (same screen, scoped). **Charts use the design system's DATA-viz colours, never the brass accent (N6).**

Screens:
- **9.1 Owner dashboard.** Fixed priority order: (1) **WHAT NEEDS YOU** first & prominent — deals going cold (pre-Won = overdue next action / no activity, e.g. "Anand Traders·Negotiating·no activity 18 days"), proposals sent-not-opened ("Priya Sharma·shared 4 days ago"), projects blocked (post-Won DO use days-in-stage, "Deshmukh Textiles·waiting on DISCOM·34 days in stage"), payments overdue ("Kavita Joshi·₹70,369 due since 20 Aug"); (2) **CASH** collected vs due this month + overdue total; (3) **PIPELINE** value/count by stage; (4) **THIS PERIOD** won value vs last vs optional target (target set INLINE, no separate targets screen, never nags); (5) **FORECAST** weighted pipeline "expected not promised"; (6) **WIN/LOSS** rate + both loss-reason lists → 9.3; (7) **AGENT** compact card → Phase 6 (no restated numbers); (8) **TEAM** per-rep snapshot (owner+manager only). Edge states: brand-new no-data (teach, never broken chart), mid-month "so far this month" (not projected), no-target, an outlier ₹92L C&I deal flagged so pipeline doesn't look healthier than it is, manager view team-scoped. My pipeline value/count by stage; my win rate; proposals out/opened/accepted; follow-up load (due/overdue); optional target. Results as-you-type; recent/suggested before typing.

### Phase 10 — The Design Studio · 11 screens (SUPERSEDED as a redesign — kept as inventory)
**Thesis:** the studio already exists and works in code — real satellite imagery, AI roof detection, PVGIS energy, shading simulation, auto-layout, structural material modelling, string sizing, SLD, BOM. **Keep every tool and every computed output through the refactor.** Redesign brief (now the production-studio target): preserve every tool; mode-based canvas not modifier keys (choose Select/Draw/Panels/Measure first, then canvas obeys); add touch gestures the 2D canvas lacks (pinch-zoom + two-finger pan; 3D already has touch orbit/pinch); visible labels not hover; big tap-to-select-then-edit targets (replace ~9px handles); progressive disclosure (BOM's ~286 controls → card list + edit sheet); **honesty not optional** — carry provenance labels measured/derived/estimated/assumed, PVGIS vs estimate, structure = material modelling only never a safety verdict (engineer sign-off is human). Two viewports each screen (mobile 375 hard case must fully work; desktop 1440 richer). Editor steps dark canvas, form steps light.

**Key facts (code corrects common assumptions):** Energy = **PVGIS** (annual+monthly generation, specific yield, performance ratio, POA, loss breakdown, 25-yr, degradation) with built-in latitude-estimate fallback, always labelled. **Google Solar API is a separate ENHANCEMENT never a dependency** (Building Insights: max panels, roof area, sunshine h/yr, per-face pitch/azimuth, imagery date+quality; India partial coverage → loading/unavailable/unreachable/ok states). **AI roof detection** = geometric (Google dataLayers DSM+mask → outline, pitch, azimuth, eave height, obstructions, confidence from plane-fit RMSE) with **Gemini photo fallback** (polygons + obstructions but cannot measure height/pitch); both reviewed as **ghosts** before entering. **Electrical hard gate:** invalid string design blocks "Next" on the layout step. **Design Health** (0–100; energy/electrical/roof-utilisation) rides in the shell header.

The 11 studio screens: 10.1 shell + design list + Design Health; 10.2 Step 1 project setup & location (+PVGIS, Google Site Intelligence); 10.3 Step 2 roof setup (AI detect + touch-first CAD tracing); 10.4 Step 3 obstructions; 10.5 Step 4 components; 10.6 Steps 5–6 panel layout (auto-fill + manual editor + structure); 10.7 the 3D view; 10.8 Step 7 proposal captures & readiness; 10.9 Step 8 SLD & drawings; 10.10 Step 9 BOM & pricing; 10.11 Step 10 done + engineer sign-off. (Full tool census in §2.)

## 2. TOOL / FEATURE CENSUS (Phase 10, screens 10.1–10.11)

### 10.1 Shell + design list + Design Health
- **Entry/design list:** studio opens from lead "Create design"; a lead holds SEVERAL variants (each shows size, generation, price, payback; one "recommended"); New design / duplicate / open.
- **10-step wizard:** 1 Project setup · 2 Roof · 3 Obstructions · 4 Components · 5 Panel placement (auto — no page of its own) · 6 Manual edit · 7 Proposal · 8 SLD & drawings · 9 BOM & pricing · 10 Final. Step states: not started / in progress / done / has errors. Compact step indicator (mobile "3 / 10 · Roof ‹ ›" → step-list sheet; desktop step rail).
- **Header controls:** back, step title, **Design Health chip**, units toggle (m/ft, global), Save, Save & exit to lead, Help (per-step plain language, folds old keyboard cheats into on-screen help), Next/Done.
- **Per-step Next gate** with plain reason ("Draw at least one roof", "Fix the string design before continuing"); hard electrical gate on layout step.
- **Design Health:** score /100 + band **Good/Fair/Poor** across energy, electrical, roof-utilisation; health sheet shows per-category scores, specific deductions ("−8 · off-south orientation"), and a "what changed since last save" delta; provisional state while shading recalculates.

### 10.2 Step 1 · Project setup & location
- **Pre-fill from survey (Phase 5):** address/location/site details carried over, editable.
- **Fields:** project name; customer name; customer phone; Country (India); State; DISCOM (sets default tariff); Site type Residential/Commercial; Connection Single/Three phase; Sanctioned load (kW); Electricity tariff ₹/kWh (auto-filled, editable); Average monthly bill ₹ (feeds Step-4 size suggestion); Company logo upload (max 5 MB, PNG/JPG); Ground-mount / open-access project (normal option, no PRO/tier gate D38; if not functional mark "coming soon" not "upgrade").
- **Location:** search address (autocomplete) OR enter coordinates; satellite map (redesign pin placement — code has a FIXED pin + drag-map-underneath, confusing on touch; still land on exact roof; keep zoom); "Confirm location" → **Solar Data card** (irradiance kWh/m²/day, peak sun hours, source label → becomes PVGIS-measured once fetched).
- **Site Intelligence (Google Solar Building Insights):** async, four states loading/unavailable/unreachable/ok; ok shows max panels (~kWp), roof area, sunshine h/yr, roof faces, imagery date + quality (HIGH/MED/BASE).
- **Guard:** relocating pin **>25 m WIPES the whole design** (roofs, panels, etc.) — keep guard, make it a clear undoable confirmation not a silent reset.

### 10.3 Step 2 · Roof setup (touch-first CAD)
- **Mode toolbar:** Select · Draw roof · Detect roofs (AI) · Ortho-snap toggle · Show all measurements · Measure distance · View in 3D · Undo · Redo.
- **AI Detect:** geometric pipeline (Google dataLayers → outline, pitch, azimuth, eave height, obstructions, per-shape confidence) then Gemini photo fallback (shapes only, no height/pitch); results as **ghosts** to accept/reject (tap ghost include/exclude, align nudge, "add selected", imagery quality/date, dropped-shape warnings).
- **Roof list:** one chip per roof (select · lock · delete, with area).
- **Drawing (touch):** choose Draw → tap corners; live edge-length labels; CAD snapping (angle-relative, object-snap to other roofs, alignment guide rays, right-angle marks) with visible snap on/off; tap near first point to close; "complete shape?" confirm; undo/last-point-remove; rejects too-close points with a plain message.
- **Editing a roof (tap-select → big handles):** move vertex · insert vertex on edge · delete vertex · move whole roof · rotate whole roof (snap-to-15° control) · tap edge length to type exact metres. Per-roof action set: roof type · height & parapet · exact vertex coordinates (X/Y) · duplicate.
- **Roof type sheet:** RCC flat · Metal shed · Tile · Ground array; where footprint allows Pitched gable (2 faces) or Pitched hip (4 faces) with ridge direction; disabled options explain why.
- **Height & parapet sheet:** height-from-ground; "Google detected N° facing DIR — apply/dismiss" pitch/azimuth suggestion banner; pitch; "slopes toward" picker (tap low edge, compass read-out, "south is best" tip); edge setback (uniform + per-edge); parapet-wall toggle → direction, height, width, auto-skip shared walls, per-side "tap a side to add/remove its wall."
- **Calibration:** measure two points → enter actual metres → applies scale correction (+ expert north offset); rescales all geometry.
- **Dependent-items guard:** geometry change orphaning downstream items → "keep current / keep for review / remove invalid."
- Carries roof provenance (manual / AI-detected + confidence). Add pinch-zoom + two-finger pan (missing in code).

### 10.4 Step 3 · Obstructions
- **Always on screen:** satellite canvas with Step-2 roofs as READ-ONLY backdrop (fill + red-dashed setback inset); every obstruction to scale with a small **ID chip** (type code + number, e.g. WT1, TR2; constant screen size at any zoom); a red-dashed **setback ring** per blocking object; north indicator; graphic scale bar; zoom in/out + live zoom % + fit view; pan/zoom free except while placing/mid-drag; undo/redo (one gesture = one step); units (m/ft).
- **Five tools:** (1) Add obstruction (badge = current count) → type picker; (2) Show/Hide obstructions (also clears selection); (3) Show all measurements (roof + rectangular-obstruction edge labels); (4) Measure distance (two-point ruler, restarts clear prior); (5) Open 3D view (→10.7, returns).
- **Type picker — ELEVEN types** with icon, name, default L×W×H (m): Tank WT 2×1.5×1.2 · Dish DS 1×1×1.2 · Chimney CH 0.8×0.8×2 · Tree TR 3×3×5 · Elevated EL 3×2.5×2.6 · Building BL 8×6×9 · Solar WH SW 2×1.2×1.5 · **Ladder LD 0.6×1.5×3 (BETA marker)** · Windmill WM 1.8×1.8×3.5 · Turbine Vent TV 0.4×0.4×0.5 · Other OB 1.5×1.5×1. Choosing → placement mode ("Click to place {type} · Esc to cancel"); next tap drops at default size; app auto-detects which roof it sits on (or "on ground") and auto-names (WT1, WT2…); cancellable.
- **Selecting an object → (a) direct manipulation:** move (grab point stays under finger, re-checks roof on release), resize rectangle (4 corner handles L/W), resize circle (1 handle diameter), rotate (stem handle, 15° snap or free); **no dimension below 0.3 m**; locked object can't move/resize/rotate.
- **(b) Context action set (exactly seven):** Duplicate (offset copy, recomputes roof) · Shape · Size & rotation · Settings · Lock/Unlock · Delete · Deselect. Precise positioning without a mouse: fine + larger nudge steps, rotate in exact degrees.
- **Shape options:** Rectangle (L×W) or Circle (diameter), switchable.
- **Size & rotation:** typed exactly in current unit; Rectangle L/W/H; Circle diameter/H; Rotation 0–359° in 1° steps. Height drives shadow + bridging maths.
- **Settings (how object affects design):** SETBACK 0–3 m in 0.1 m steps (draws red ring, "buffer zone where panels cannot be placed"); CASTS SHADOW on/off (inclusion in shading sim); **BLOCKS PANEL PLACEMENT on/off → reveals nested bridging chain**: Panels may bridge above on/off → Must remain open to sky on/off → when OFF reveals Clearance above it 0–1 m in 0.05 m steps with a live calc "Bridgeable when the array structure clears X m (its Y m + margin)" + a warning that bridging is flagged for engineer confirmation. CONVERT TO ROOFTOP PLATFORM (one-tap: replaces obstruction with a new roof surface "{label} platform" at roof height + own height so panels mount on top; states structural adequacy needs engineer verification; unavailable when top too small, reason shown). HEIGHT INFORMATION (read-only: placement roof name or "On ground", base surface height, top-from-ground).
- **Live updates:** owning roof (re-checked on move), base/top heights, required bridging clearance, setback ring size, total count.

### 10.5 Step 4 · Components
- **Three parts in order: Panel → Capacity → Inverter** (each shows done-state + current choice, reopenable).
- **Panel:** selected-panel summary (brand, model, dimensions, Voc/Vmp/Isc, wattage large); Search; **Filters** (min/max watt; Technology: All Types · Mono PERC · TOPCon · Bifacial · Poly · HJT; DCR on/off; ALMM on/off); result count; list rows (brand mark, brand+model, "watt · technology · dimensions", ALMM/DCR badges); two "available-later" routes: enter specs manually + upload datasheet (PDF extraction).
- **Capacity:** target capacity kWp (0.1 steps); **Auto** = maximum fit after setbacks + obstructions (unavailable until panel chosen + roof exists); Google Solar cross-check line ("estimates max N panels ~X kWp", info only); **bill-based suggestion** ("From your ₹X/month bill we recommend ~Y kWp", tap applies, X from Step 1); Continue unavailable while capacity 0.
- **Inverter:** recommended line ("Recommended: {brand} {model} ({kW}×{count}, {phase}) → DC/AC ratio X", tap applies); selected summary (brand, model, #MPPTs, voltage range, phases, efficiency, kW large); number of inverters 1–10; **DC/AC ratio live health: >1.35 high (clipping risk), <0.90 low (oversized), 0.90–1.35 healthy**; search + count + list (kW · phase · MPPT count · voltage range, recommended badge). After inverter chosen: **DC collection topology** (String inverters / Central + combiners), **MLPE** (None / DC optimisers).
- **Compare options** (unavailable with no roof): states BASIS (target vs max fill, PVGIS vs built-in estimate, catalog version, warnings); per-candidate comparison: Option (panel, RECOMMENDED/CURRENT markers, on-order/DCR note) · Inverter (+DC/AC ratio) · Fits (panels×watt→kWp) · Module efficiency · Annual generation kWh · Net cost (subsidy shown separately) · Payback · 25-year savings (+ROI%) · Warranty (panel/inverter yrs) · Install (complexity + array weight) · Apply/selected/feasibility; decision cards (topic, choice, reason, inputs); fixed-assumptions footnote (tariff escalation/yr, 25-yr horizon, margin, PM Surya Ghar subsidy); Apply sets panel+inverter+count in one undoable action; if panels already placed with a different panel → replace-panel confirmation.
- **Live updates:** module efficiency, annual kWh, net cost, subsidy, payback, 25-yr savings, ROI%, DC/AC ratio, array weight, install complexity, valid-string existence, recommended inverter+count, effective kWp roofs hold, bill-based suggestion.

### 10.6 Steps 5–6 · Panel layout (most tool-dense screen)

## 3. ENGINEERING RULES (quantitative)

**Electrical / string design (10.5, 10.6, 10.9):**
- DC/AC ratio bands: **>1.35 = high (clipping risk); <0.90 = low (oversized); 0.90–1.35 = healthy.**
- Hard electrical gate blocks Next while invalid. Validation errors: string voltage too high in cold; voltage below MPPT window; panel current above MPPT input; DC/AC too high/low; panels unstrung; more strings than MPPT inputs; "no valid string length exists for this panel/inverter pair."
- Manual stringing tracks running **cold-weather string voltage** live, coloured over-limit / under-MPPT-floor / fine; warns too-long/too-short; refuses already-used or disabled panels.
- Auto-string groups panels into valid strings per inverter MPPTs + auto-routes DC + AC.
- **Maximum system voltage compliance (10.9):** longest string cold-weather voltage vs inverter max DC voltage; over = fault ("shorten the string"). This is the inspector-checked figure.
- Inverter count 1–10; number of MPPTs, voltage range, efficiency, phases tracked per inverter.
- DC-side ratings menu: cable 2.5/4/6/10 mm²; fuse 15/20/25/32 A; SPD Type-I / Type-II / Type-I+II; isolator 25/32/40/63 A. AC-side: cable 4–95 mm²; type PVC copper / XLPE copper / XLPE aluminium; MCCB A (also sets isolator); SPD type. Standard: IS/IEC 62548·CEA, IEC 60364-7-712, or NEC 690.

**Roof / geometry (10.2, 10.3):**
- Pin relocation **>25 m wipes the entire design.**
- Roof AI confidence from **plane-fit RMSE** (geometric); Gemini fallback gives shapes only (no height/pitch).
- Roof types: RCC flat, Metal shed, Tile, Ground array, Pitched gable (2 faces), Pitched hip (4 faces).
- Calibration: measure two points → enter real metres → scale correction + expert north offset, rescales all geometry.

**Obstructions (10.4):**
- 11 types with default L×W×H (see census); **minimum dimension 0.3 m**; rotation 0–359° in 1° steps.
- Setback 0–3 m in 0.1 m steps (draws red keep-out ring).
- Bridging clearance 0–1 m in 0.05 m steps; live rule "Bridgeable when the array structure clears X m (its Y m + margin)"; bridging flagged for engineer confirmation.
- Height drives shadow + bridging maths; app auto-assigns owning roof on placement/move.
- Convert-to-platform sits at (roof height + object height).

**Structure estimation (10.6, 10.7) — material modelling ONLY, never a safety verdict:**
- Structure presets: Flush · Standard 10° · Walk-under 2.2 m.
- Racking: Flush · Fixed tilt · Dual tilt. Panel tilt 0–35° (5° steps). Clearance 0–3 m (0.3 m steps). Leg spacing 0.5–4 m. Azimuth ±5° steps, Due South / Roof slope presets.
- Member model counts legs, rafters, purlins, braces (count + total metres) + total steel kg; structure profile = steel section w/ weight per metre.
- Ground foundation: Driven pile / Ballasted (soil survey required). 3D foundations: PCC pedestal / Chemical anchor / Ballast block / Driven pile; shuttering Square/Circular (circular ≈ ⅕ less concrete). Purlins per row 1–6; rafter density 1–3× (half steps, a material allowance not a safety factor); end overhang 0–1 m; bracing on/off.
- Inter-row shading: recommended winter shadow-free row pitch (m) + resulting **GCR** + one-tap "Apply shadow-free spacing."
- **Structure disclaimer mandatory everywhere:** material estimate + visual model, NOT a wind/uplift/roof-capacity check; engineer verifies. Foundation sizes nominal + assumed, add roof weight, roof capacity not checked. High-wind marker derived from site state → engineer verification mandatory.

**Energy (PVGIS) (10.6, 10.7):**
- PVGIS = annual + monthly generation, specific yield (kWh/kWp), performance ratio %, POA factor, loss breakdown, 25-yr projection, degradation. Built-in latitude-fit fallback labelled "±10%."
- Losses itemised with %: temperature, soiling, inverter, mismatch, DC wiring, measured shading, + total.
- 25-year projection: lifetime MWh + year-25 output as % of year 1.
- Heatmap kWh/m² carries "Real · PVGIS" marker; geometric solar-access numbers deliberately carry NO such marker.

**BOM / pricing rules (10.10):**
- Margin editable 0–60%; discount value + % or ₹; GST per-line 0–40% (per-rate breakdown when mixed); waste 0–100%; order quantity = quantity + waste, rounded up for whole-unit items.
- Confidence taxonomy MEASURED / DERIVED / ESTIMATED / ASSUMED.
- Six categories fixed order: Modules · Inverter · Electrical BOS · Mechanical BOS · Safety · Civil & Misc.
- Cable sizing survey inputs: Average DC run + Average AC run (locked to routed geometry when it exists).
- **BOM totals ARE the proposal's money path — the same arithmetic; the two can never disagree.** Rates read from Phase-8 price book (versioned).
- Below-cost warning when discount sells under cost.

**Finance rules (across 10.5/10.7/10.10 + Phase 7):**
- Subsidy = **PM Surya Ghar** (with DCR/domestic-content caveat for eligibility); subsidy shown separately from net cost; when ₹0, reason shown.
- Fixed-assumptions footnote: tariff escalation per year, 25-year horizon, margin, PM Surya Ghar subsidy.
- Financials: net cost after subsidy, yearly savings at tariff, payback years, 25-yr savings + ROI%; financing options = representative terms only.
- Payment tranches: **10/60/20/10** default (booking / material dispatch / installation / commissioning); other templates 30/60/10, 50/50; **every set must total 100%.** Passed milestone → tranche due.
- Financial defaults (Phase 8.4): subsidy, GST %, tariff ₹/kWh, inflation %, AMC default, EMI interest — sensible India values.

**Insights / health scoring:**
- **Design Health 0–100**, bands Good / Fair / Poor, across three categories: energy, electrical, roof-utilisation; itemised deductions ("−8 · off-south orientation"); "what changed since last save" delta; provisional while shading recalculates.
- **Days-in-stage** is the single project health metric (Phase 7) — an aged card must read as stuck, never "nearly finished."
- **Forecast = weighted pipeline** (value × stage likelihood), "expected not promised," never summed with won.
