# SCR-MS-08 · Studio Step 6 — Layout Editor

2D canvas to place/group panels, draw safety elements, string, parameterise tables, and pass the hard gate.

**Module:** M05 · Design Studio · **Personas:** Design Engineer (author), Design Engineer with sign-off capability (review), Sales Executive (read/3D walkthrough), EPC Owner · **Context of use:** the studio's most tool-dense screen, worked at a desk on web and in the field on the phone — web primary with mobile full parity per the studio touch law (mode-based tools, touch-equivalent controls for every keyboard nudge, on-object direct manipulation working at 375 px per M05-91's DoD note); long editing sessions on one design record; the canvas is light like every other surface — v1 is light-only, with no dark theme and no dark variant of any surface (`foundations/F7`, `F7-04`, P0; the shell carries the same law, SCR-MS-03).

## Entry & exit

Reached from: the studio shell's step navigation (SCR-MS-03) — this is the wizard's Panel layout step, with auto-placement folded in so no user-visible "step 5" exists (per the M05 §M05.7 note: arrival options carry `R7`, the fold is this section). **Wizard-step gate that admits the user:** the per-step Next gates of the earlier steps (M05-05 family, SCR-MS-03) — arrival presumes roofs from Step 2 and the Step-4 target capacity (M05-44 auto-fills "to the Step-4 target"; MS6-01 is written for "Arriving with roofs but no panels"). Leads to: Step 7 — Proposal (SCR-MS-10), but **only through the studio's one hard gate**: invalid electrical blocks the next step with the reason stated (M05-49, MS6-28); the Studio 3D Scene (SCR-MS-09) is one tap away (M05-50); "Why this layout?", table settings, stringing and string-connections sheets open over this canvas.

## States

- loading — the shell's hydration gate shows loading rather than a blank screen, so the canvas is never drawn empty while a 221-panel design hydrates (MS12-27, shell contract on SCR-MS-03). Heatmap and shading work have their own progress state below, not this one.
- empty (empty-no-panels — arrival with roofs but no panels; the arrival offer, not a blank canvas: Place manually · Auto-fill panels · Use maximum roof capacity, M05-44/MS6-01)
- error — a load or recompute that fails says so rather than rendering a plausible-looking canvas: per-panel and health figures are keyed to the design + shading + insight state so a stale score can never show in place of a failed one (MS6-52), and a shading recompute in flight renders provisional, never stale-as-current (M05-06, shell contract). Design-rule failures are not this state — they are the live validation banner (MS6-27) and the hard gate (MS6-28).
- save-failed-persistent-alert — **the save failure is loud and persistent.** Design mutations fail fast: a failed save says so honestly at the attempt — never a silent no-op, never an optimistic result — and a stale save is refused, never merged, with the client reloading server state and the user re-applying the change (M05-09). The save-state alert is persistent, not a toast: a "not saved" alert stays up while writes are failing and the design never silently loses work (MS12-24, shell contract) — over a 221-panel canvas this must stay visible through scrolling, panning, sheet-opening and tool switching, because the cost of missing it is a whole editing session.
- undo-survives-failed-save — undo is whole-design snapshots scoped to the open design, cleared on switching designs — not on a failed save (MS12-21, `prd/modules/M05-studio/11-shell-and-platform.md`), so a refused save leaves the stack intact and the user re-applies rather than re-draws.

## Data volume

The studio's flagship scale: a 221-panel design. Four tool families with live count badges on Safety and Electrical; a validation banner aggregating layout, structure, route and system issues at once; parametric tables with counted member bills (legs, rafters, purlins, braces — counts + metres — and total steel kg); marquee selections of dozens of panels with the constant-size context bar. The P1/P2 rows extend the same surface to large-C&I blocks and utility scale, so the 2D canvas must stay workable at 221 panels on a 375 px viewport.

## Numbers carrying provenance

- Enabled panel count and achieved-vs-target kWp (status pill — M05-50, MS6-29); exceeding target is a design cue, never a cap
- DC cable length — routed vs estimate, **labelled which** (M05-50)
- Heatmap figures: current-month avg access %, avg sun-hrs/day, kWh/m² (M05-45); the heatmap is the same engine as 3D (MS6-10) where kWh/m² carries the source-of-record marker and geometric access numbers deliberately carry none (law at M05-52 on SCR-MS-09)
- Running cold-weather string voltage in manual stringing, coloured over-limit / under-MPPT-floor / fine (M05-48) — derived
- Table header rows × cols, panel count, kWp (MS6-19, M05-47) — derived
- Structure member counts, metres and total steel kg; structure profile section size and kg/m (M05-47, MS6-21) — a material **estimate**, never a safety verdict; the disclaimer and engineer-verification line travel with it (MS6-22)
- Recommended winter shadow-free pitch and resulting GCR (M05-47, MS6-20) — derived
- Design Health score across energy/electrical/utilisation (MS6-52) — keyed so a stale score can never show; context lines (irradiance provenance) shown but never scored
- Walkway widths (600/800/1000 mm or custom 100–3000 mm), tilt 0–35°, azimuth ±5°, leg spacing 0.5–4 m, clearance 0–3 m (M05-45, M05-47) — user-set parameters

Every user-visible figure carries its F8 provenance tier in the design; flat-terrain fallbacks at Tier C carry `assumed` with a visible warning (M05-92).
