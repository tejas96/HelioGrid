# Rules — packages/i18n (Lingui v5, EN/HI/MR)

- One catalog, two consumers: Next.js (App Router/RSC setup) + bare RN (metro transformer).
  Message source of truth = code macros (`t`, `<Trans>`), extracted to `.po` per locale.
- Per-USER language (D25), not per-tenant: switching re-renders the whole app immediately,
  no reload. Marathi surveyor and English owner coexist in one tenant.
- NEVER translated: kW, kWh, kWp, brand/model names, DISCOM names. ₹ always uses Indian
  digit grouping (₹4,52,471; ₹92L; ₹1.4 Cr) in every locale — one shared `formatInr()`
  from packages/domain units module; never Intl defaults for currency grouping.
- Devanagari: font chain Inter → Noto Sans Devanagari (web automatic per-codepoint; RN
  needs explicit fallback handling — verify rendered output, not just config).
- Layouts must survive text expansion (~20–30% for Hindi/Marathi): no fixed-width labels,
  no truncation of amounts or units. Every new screen ships with its Hindi render checked.
- Message hygiene: no string concatenation for sentences; ICU plurals/selects; placeholders
  named (`{customerName}`), never positional. Agent-facing templates (WhatsApp message
  templates) are tenant DATA in all three languages, not catalog messages.
- Adding a locale later = new .po + font check + number-format review. Nothing else may
  need to change — if it does, the change that caused it was wrong.
